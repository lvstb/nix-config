# Herdr integration

Install a flake-provided application through Home Manager.

---

## Provide context

This repository imports `nixos-unstable` as its primary `nixpkgs` input and builds one shared package set with a local overlay list in `flake.nix`.

`home/apps.nix` consumes that package set through `home.packages = with pkgs; [...]`, so adding `pkgs.herdr` there makes the application persistent for both configured Home Manager profiles.

---

## Define goals

- Add `github:ogulcancelik/herdr` as a flake input.
- Make the Herdr input follow this repository’s `nixpkgs` input.
- Add Herdr’s default overlay to the existing overlay list.
- Install `pkgs.herdr` persistently through `home/apps.nix`.
- Keep package resolution consistent across Home Manager and NixOS package sets.

---

## Exclude extras

- Do not add a separate `packages.${system}.herdr` output.
- Do not add a custom Herdr overlay or local package definition.
- Do not change Herdr configuration, services, shell integration, or secrets.
- Do not alter unrelated existing worktree changes.

---

## Build architecture

Declare a `herdr` input in `flake.nix` with URL `github:ogulcancelik/herdr` and `inputs.nixpkgs.follows = "nixpkgs"`.

Append `inputs.herdr.overlays.default` to the existing `overlays` list, allowing the existing `pkgs = import nixpkgs { ... overlays = overlays; }` expression to expose `herdr` as `pkgs.herdr`.

Add `herdr` to the application-oriented portion of `home/apps.nix`’s `home.packages` list. Do not duplicate it in the flake’s custom package output because the overlay is the intended package access path.

---

## Trace data flow

1. Flake evaluation resolves `herdr` from GitHub and locks its revision in `flake.lock`.
2. The Herdr input follows the repository’s `nixpkgs`, avoiding a separate package-set revision.
3. `inputs.herdr.overlays.default` extends the shared overlay list.
4. The shared `pkgs` import applies that list and exposes `pkgs.herdr`.
5. Both Home Manager configurations include `home/apps.nix`, so Home Manager installs Herdr for each profile.

---

## Change files

- `flake.nix`: declare the input, connect its `nixpkgs` dependency, and add its default overlay.
- `home/apps.nix`: add `herdr` to `home.packages`.
- `flake.lock`: update the lock data generated by flake input resolution; do not hand-author unrelated lock changes.

No other files should be changed by the implementation.

---

## Verify behavior

Run `nix fmt` after the Nix changes, then run `nix flake check` from the repository root.

Confirm that evaluation exposes `pkgs.herdr`, both Home Manager configurations evaluate with the package present, and no `packages.${system}.herdr` attribute was added.

Inspect the final diff and verify it contains only the three planned files plus the expected lock update. Do not print or inspect secret material during verification.

---

## State assumptions

- The Herdr flake exposes `overlays.default` and that overlay provides an attribute named `herdr`.
- The Herdr package is compatible with this repository’s `x86_64-linux` system and `nixos-unstable` package set.
- The existing shared `pkgs` value is the package set used by both Home Manager configurations.
- Updating `flake.lock` is an expected generated consequence of adding the input, while manually editing Nix files is outside this documentation-only task.
- The requested persistent installation means adding the package to the shared `home.packages` list, not enabling a separate Home Manager module.
